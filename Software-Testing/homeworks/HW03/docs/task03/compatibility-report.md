### BUG-COMPAT-001 — Fixed-width table layout causes column content loss and overflow on mobile viewports

| Field                     | Detail                                                                                                                                                                                                                                                                                                                                                                                                   |

**Expected Behaviour:** The table should either scroll horizontally within its container or reflow into a responsive card/list layout on viewport widths < 600 px, ensuring all column data is accessible.

This causes: (1) form labels and input fields to render too narrowly and overlap each other; (2) modal dialogs (e.g., date picker, role assignment inputs) to render at their desktop size without `max-width: 100vw` and `overflow: hidden` constraints, causing them to extend beyond the phone viewport. |

## 6. Recommendations

1. **Immediate (P1 — Critical):** Address BUG-COMPAT-001 and BUG-COMPAT-002. The absence of mobile responsiveness in the main table and sidebar renders the application essentially unusable on all mobile phone browsers. These should be resolved before any release targeting mobile users.
2. **Short-term (P2 — High):** Address BUG-COMPAT-003, BUG-COMPAT-004, and BUG-COMPAT-005. These affect all mobile and some tablet configurations, blocking primary user workflows (event creation, participant management, navigation).
3. **Mid-term (P3 — Medium):** Address BUG-COMPAT-006 and BUG-COMPAT-007. These are Safari-specific issues; BUG-COMPAT-006 blocks content access while BUG-COMPAT-007 is a readability/accessibility concern that should be fixed to meet WCAG AA.
4. **General:** Adopt a mobile-first responsive design strategy. Use browser developer tools (responsive mode) as a baseline and BrowserStack for final cross-browser validation before each release.
