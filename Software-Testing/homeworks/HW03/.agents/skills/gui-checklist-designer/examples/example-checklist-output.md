## IA-01 — General UI Standards

> **Scope:** layout, alignment, typography, colour consistency, i18n/l10n, empty states, loading states, responsive breakpoints, touch targets

| ID       | Description                                                                                                                                                                                         | Heuristic Ref | Widget / Area          | Priority |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- | ---------------------- | -------- |
| IA01-001 | All interactive elements of the same type (buttons, inputs, cards) are vertically and horizontally aligned on a consistent grid — no element is visually offset from its sibling group.             | S1, N4        | Page layout            | Med      |
| IA01-002 | Typography follows a visible size hierarchy: page title > section heading > body text > caption, with no two adjacent levels sharing the same size and weight.                                      | N8, S1        | Typography             | Med      |
| IA01-003 | When a list, table, or search result set contains no data, the empty area displays an explanatory message and (where applicable) a call-to-action — the area is never left blank.                   | N1, N10       | Empty state            | High     |
| IA01-004 | While an async operation is in progress (data fetch, file upload, form submit), a loading indicator (spinner, skeleton screen, or progress bar) is visible and positioned within the affected area. | N1, NOR5      | Loading state          | High     |
| IA01-005 | All UI text switches language completely and immediately when the language toggle is activated — no residual text from the previous language remains visible.                                       | N4, S1        | i18n / language toggle | High     |
| IA01-006 | All body text and interactive control labels meet WCAG 2.2 minimum contrast: ≥ 4.5:1 for normal text, ≥ 3:1 for large text (≥ 18pt regular or ≥ 14pt bold).                                         | WCAG1.4.3     | Page layout            | High     |

## IA-02 — Forms

> **Scope:** labels, inline validation, error placement, required-field marking, file upload, date/time pickers, submit behaviour, ARIA on custom inputs

| ID       | Description                                                                                                                                                                                                           | Heuristic Ref                | Widget / Area   | Priority |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | --------------- | -------- |
| IA02-001 | Every form input has a visible text label positioned outside and above (or beside) the field — placeholder text alone does not serve as the field label.                                                              | NOR2, W-TextBox, WCAG3.3.2   | Text input      | High     |
| IA02-002 | Required form fields display a consistent required indicator (e.g. asterisk `*`) adjacent to the label; optional fields display no such indicator.                                                                    | NOR2, W-TextBox, WCAG3.3.2   | Text input      | High     |
| IA02-003 | Validation feedback triggers on field blur (when the user leaves the field) — not solely on form submission — so users are informed of errors before completing the entire form.                                      | N9, S5, NOR5                 | Form validation | High     |
| IA02-004 | Error messages appear immediately adjacent to the offending field, identify the field by name, describe the error in plain language, and suggest how to fix it.                                                       | N9, S5, WCAG3.3.1, WCAG3.3.3 | Form validation | High     |
| IA02-005 | The date picker rejects logically invalid dates (Feb 30, month 0 or 13, day 0 or 32) and enforces any business range constraints (e.g. end date ≥ start date) without requiring form submission to surface the error. | N5, NOR3, W-Date             | Date field      | High     |
| IA02-006 | After a file is selected for upload, a preview (thumbnail for images) or filename confirmation is displayed, and the user can remove or replace the file before submitting.                                           | N3, N1, W-FileUpload         | File upload     | Med      |

## IA-03 — Navigation

> **Scope:** sidebar, breadcrumbs, tab panels, drag-and-drop reorder, back/return actions, deep links, keyboard tab order, focus visibility

| ID       | Description                                                                                                                                                                                                                                                  | Heuristic Ref              | Widget / Area      | Priority |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- | ------------------ | -------- |
| IA03-001 | The sidebar or main navigation menu displays a clear visual indicator (highlight, bold text, or active marker) on the item corresponding to the currently active page.                                                                                       | N1, NOR4, W-Sidebar        | Sidebar nav        | Med      |
| IA03-002 | Navigating via the browser's Back button returns the user to the expected previous state without triggering an error page, data loss, or unexpected redirect.                                                                                                | N3, S6, W-Sidebar          | Browser navigation | High     |
| IA03-003 | Every interactive element on the page is reachable and operable using the keyboard Tab key alone, in a logical order that follows the visual reading sequence of the page.                                                                                   | S2, WCAG2.1.1, WCAG2.4.3   | Full page          | High     |
| IA03-004 | A visible keyboard focus indicator (outline, glow, or underline) is present on whichever element currently holds keyboard focus — focus is never invisible or obscured by a sticky header or overlay.                                                        | WCAG2.4.7, WCAG2.4.11      | Full page          | High     |
| IA03-005 | During a drag-and-drop reorder operation, the dragged item shows visual feedback indicating its current state (e.g. reduced opacity), drop targets provide a visual insertion indicator, and the reordered sequence is persisted after the action completes. | N1, NOR4, NOR5, W-DragDrop | Drag-and-drop      | Med      |
| IA03-006 | Every drag-and-drop reorder operation has a keyboard-accessible alternative (e.g. move-up / move-down buttons) that achieves the same outcome.                                                                                                               | S2, WCAG2.5.7              | Drag-and-drop      | High     |

## IA-04 — Feedback / State

> **Scope:** toast notifications, confirmation dialogs, status badges, progress bars, real-time updates, disabled states, status announcements

| ID       | Description                                                                                                                                                                                                                                          | Heuristic Ref          | Widget / Area       | Priority |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ------------------- | -------- |
| IA04-001 | After every create, update, delete, or submit action, a toast or equivalent notification confirms the outcome (success, failure, or partial result) in consistent, specific language — not only a generic "Operation completed."                     | N1, S3, NOR5, W-Toast  | Toast notification  | High     |
| IA04-002 | Toast notifications appear in a consistent position across all screens (e.g. always top-right or always bottom-center), use semantic colours (green=success, red=error, yellow=warning, blue=info), and do not obscure primary interactive controls. | N4, S1, W-Toast        | Toast notification  | Med      |
| IA04-003 | Destructive or irreversible actions (delete, publish, block user) trigger an explicit confirmation dialog before execution — the action cannot be completed with a single accidental click.                                                          | N3, S6, NOR3, W-Modal  | Confirmation dialog | High     |
| IA04-004 | Status indicators (badges, labels, icons representing state such as active, pending, rejected) convey their meaning through both colour and a text label or icon — colour is never the sole means of communication.                                  | N4, WCAG1.4.1, W-Toast | Status badge        | High     |
| IA04-005 | Controls that are disabled because a prerequisite has not been met display a visually distinct disabled state (reduced opacity, no hover effect) and, where the reason for disabling is non-obvious, include a tooltip or adjacent explanation.      | N1, NOR2, W-Button     | Disabled control    | Med      |
| IA04-006 | Success and error messages rendered after form submission are announced to assistive technology without requiring the user to move focus to the message element.                                                                                     | WCAG4.1.3, NOR5        | Status message      | High     |
