# Example: Usability Test Plan

> **SUT:** Generic Web Admin Panel  
> **Test type:** Assessment

This example shows the complete 9-part test plan format. The file output is `test-plan.md`.

```markdown
# Usability Test Plan — Generic Web Admin Panel

> **Test type:** Assessment  
> **Generated by:** `usability-test-designer` skill (v1.0.0)  
> **Sessions:** 5 participants | 1 task | Moderated

## 1. Purpose

This test evaluates whether first-time admin users can create, configure, and publish an event using the system's event management interface. Results will inform usability improvements before the system goes into production use.

## 2. Problem Statement

- Can a first-time admin user create and publish a complete event without assistance?
- Which steps in the event creation flow cause the most hesitation or errors?
- How long does it take a competent user to complete the full event setup workflow?
- Do participants trust that the event has been successfully published after they finish?
- What is the overall perceived usability of the system (SUS score)?

## 3. Test Objectives & Tasks

**Objective:** Identify friction points in the event creation and publication workflow that cause errors, hesitation, or task failure for first-time admin users.

| Task ID | Title                                                | Screens covered                                  |
| ------- | ---------------------------------------------------- | ------------------------------------------------ |
| T1      | Create and publish an event with registration limits | A2: Add/Edit Event Form, A3: Registration Config |

Full task scenario → see `task-scenario-T1.md`

## 4. User Profile

**Target participant:** Faculty staff or senior university students (Year 3+) who are comfortable using web-based administrative tools (e.g. Learning Management Systems, scheduling tools) but have no prior experience with this system.

**Inclusion criteria:**

- Age 20–55
- Uses a computer and web browser at least 3 times per week
- Has some experience with any web-based admin or management tool

**Exclusion criteria:**

- Has used this system before (even as a participant / attendee)
- Is a member of the development or QA team
- Is currently enrolled in the software testing course associated with this project
- Has seen the system demonstrated in a class or presentation

**Recruitment:** Via direct outreach to faculty colleagues and senior student peers not enrolled in the testing course. Minimum 5, target 6 (one spare in case of cancellation).

## 5. Method & Test Design

- **Test type:** Assessment (mid-stage — product is functional; quantitative metrics collected)
- **Session format:** Moderated in-person (facilitator present; sessions recorded with consent)
- **Design:** Single-condition (one variant; no A/B comparison)
- **Number of participants:** 5
- **Tasks per session:** 1
- **Estimated session duration:** 45–60 minutes
  - Briefing + think-aloud practice: ~10 min
  - Task T1: ~15–20 min (benchmark: 8 min; allow 2× for first-time users)
  - SUS + probe questions debrief: ~15 min
  - Wrap-up: ~5 min

## 6. Environment & Equipment

| Item             | Value                                                                     |
| ---------------- | ------------------------------------------------------------------------- |
| SUT URL          | [Facilitator fills before sessions]                                       |
| Test account     | Admin account with no pre-existing events                                 |
| Device           | Facilitator's laptop (Windows 11 or macOS)                                |
| Browser          | Google Chrome (latest)                                                    |
| Screen recording | OBS Studio (free, local recording)                                        |
| Audio            | Built-in microphone; participant consent obtained before recording        |
| SUS delivery     | Printed paper form handed to participant after tasks                      |
| Task scenario    | Printed on paper and placed face-down; given to participant at task start |

## 7. Test-Monitor Role

**Before the session:**

- Open the SUT and log in with the test admin account
- Clear any events created in previous sessions
- Start screen recording before the participant sits down
- Prepare printed task scenario and SUS form

**During the session:**

- **Introduce purpose:** "We are testing the system, not you. There are no wrong answers."
- **Explain think-aloud:** "Please say out loud what you are thinking as you work."
- Practice think-aloud with a 60-second warm-up task (e.g. "Find the weather in Hanoi online")
- Hand the printed task scenario to the participant; start the stopwatch
- Observe neutrally. **Record:** `[MM:SS] | behaviour | verbalization | observer note`
- If participant is silent > 30 seconds: neutral prompt — "What are you thinking right now?"
- **Do not hint, guide, or confirm** any action the participant takes
- **Intervention threshold:** If fully stuck with no progress > 5 minutes — record as Partial/Failed; ask "What would you expect to happen here?" then may offer one hint (record: "facilitator hint given at MM:SS")
- Stop stopwatch when participant declares done or abandons

**After the session:**

- Administer SUS (printed form, ~3 minutes)
- Ask probe questions from probe-questions-T1.md (~10 minutes)
- Thank participant; answer any questions they have

## 8. Evaluation Measures & Data to Collect

### Performance Metrics (Objective)

| Metric           | Definition                                                                                                                                                                                                                         | How Measured                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Task Success     | **Completed:** event publicly visible with correct slot limits.<br>**Partial:** event saved but not published, OR published with wrong limits.<br>**Failed:** abandoned, required help to finish, or outcome does not match brief. | Facilitator judgment at task end                         |
| Time on Task     | Seconds from when participant begins reading the task to when they declare done or abandon                                                                                                                                         | Stopwatch (started when participant picks up task sheet) |
| Error Count      | Number of incorrect navigation paths, wrong form submissions, or input mistakes requiring correction                                                                                                                               | Facilitator tally in observation log                     |
| Hesitation Count | Number of pauses > 5 seconds with no action and no verbalisation                                                                                                                                                                   | Facilitator tally; note timestamp                        |

### Preference Metrics (Subjective)

| Instrument         | Description                                               | When            |
| ------------------ | --------------------------------------------------------- | --------------- |
| SUS                | 10-item System Usability Scale (Brooke 1996); score 0–100 | After all tasks |
| Probe Questions T1 | 5 open questions specific to Task T1                      | After Task T1   |

## 9. Report Contents

The usability report will include:

- Executive summary (1 paragraph)
- Methodology overview (test type, participants, tasks, tools)
- Participant table (P1–P5, masked contacts, profile summary)
- Task scenario used (T1)
- Performance metrics summary table: all 5 participants × task success / time / errors / hesitations
- SUS scores: individual + mean + adjective rating
- Findings list ranked by severity (Nielsen 0–4): each finding includes: description, heuristic violated, severity, frequency (how many Ps), recommendation
- Prioritised recommendations (top 5)
- Appendix A: raw session notes (P1-session.md through P5-session.md)
- Appendix B: raw SUS responses
```
