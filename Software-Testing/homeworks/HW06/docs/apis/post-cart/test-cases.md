## Manual Extension TCs — 5 Additional Cases

| TC ID           | Category               | Why AI typically misses this                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TC-FR07-SEC-013 | SEC — Security         | AI designs security TCs as single-request vectors. Multi-user cart isolation requires two auth sessions plus a read-back step (GET /api/cart) to verify cross-contamination did not occur. AI rarely generates end-to-end cross-user flows because they span multiple requests and require coordinating two separate JWT tokens simultaneously.                                                                                                                |
| TC-FR07-FR-020  | FR — Functional        | AI performs BVA on numeric ranges (min, max) but frequently overlooks **precision constraints** (e.g., 2 decimal places). The constraint is explicitly stated in the contract (`precision up to 2 decimal places`) but AI does not automatically translate decimal precision into a distinct boundary test case — it typically only tests 0 and negative values.                                                                                               |
| TC-FR07-ST-008  | ST — System Data State | AI generates data-state TCs for success and rejection scenarios, but rarely tests **persistence boundaries**. The contract's known constraint (cart is in-memory only) is a black-box behavioral fact: calling GET /api/cart after restart must reflect an empty cart. AI avoids testing system restart effects because they are considered white-box, but the persistence behavior is fully observable through the API.                                       |
| TC-FR07-FR-021  | FR — Functional        | AI defaults to ASCII-only test data. For a **Vietnamese e-commerce system**, localized Unicode characters (diacritics like ă, ơ, ề) in the `name` field are the primary use case, not an edge case. AI omits localization testing unless the contract explicitly states "supports Unicode" — but any real QA engineer writing for a Vietnamese SUT would include this by default.                                                                              |
| TC-FR07-ERR-012 | ERR — Error Handling   | AI generates wrong Content-Type tests mainly when it is a standalone TC category. For cart specifically, AI tends to focus on domain field validation once auth is proven to work. The scenario where a **valid authenticated user** sends a correct body but with the wrong Content-Type header is frequently missed — it is a distinct failure path from missing auth or invalid body, and exercises the body-parser middleware's content negotiation layer. |
