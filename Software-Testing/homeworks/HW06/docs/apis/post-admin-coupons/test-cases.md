Using a known seed coupon code directly verifies the uniqueness constraint fires on real populated data, not only on a code created during the test — a more realistic and regression-critical scenario.                              |
| TC-FR17-SEC-006 | SEC — Security       | AI generates role-check TCs (user token to 403) but rarely tests **forged admin tokens** using publicly known secrets. The EShop SUT has a hardcoded JWT secret. A QA engineer with SUT knowledge would craft a token with role=admin to verify whether a forged token bypasses the auth check — a critical regression test that AI avoids because it requires white-box setup knowledge.         |
| TC-FR17-ST-005  | ST — State           | AI generates data-state TCs to confirm row insertion but misses verifying that **`is_active` is server-controlled and cannot be overridden by the caller**. This requires sending is_active:0 in the request body, then reading the created coupon back (via GET /api/coupons) to assert is_active = 1. AI omits this because it involves a post-condition assertion via a second API call.       |
| TC-FR17-ERR-011 | ERR — Error Handling | AI generates wrong Content-Type tests mainly as a standalone category. For admin endpoints, AI focuses on role and auth validation after auth is proven to work. The scenario where a **valid admin user** sends a correct body with Content-Type: text/plain is frequently missed — it is a distinct failure path exercising body-parser middleware content negotiation, not auth logic.         |
