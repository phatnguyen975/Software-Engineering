# AI Critique

Based on the analysis of 48 total interactions recorded across the three AI audit logs (`post-register`, `post-cart`, and `post-admin-coupons`), the AI achieved an average Acceptance Rate (VALID + PARTIAL) of approximately 55% and a Revision Rate of 45%, with zero outright failures (INVALID). While the AI was highly capable, several shortcomings, biases, and incomplete behaviors emerged during the collaboration.

**Where the AI fell short:** First, the AI exhibited limitations in managing cascading changes across long-context documents. For example, when instructed to delete an invalid test case, it successfully removed the entry but forgot to renumber the subsequent Test Case IDs to maintain a sequential order, requiring a follow-up prompt. It also occasionally missed small spots when applying widespread refactoring across Postman collection JSON scripts, leaving behind isolated obsolete variables that required manual cleanup.

Second, the AI struggled with execution environment nuances. It generated Postman test assertions that were theoretically correct but failed in practice. For instance, it strictly asserted `Content-Type: application/json`, which failed because the Express framework automatically appends `charset=utf-8`. Additionally, the AI failed to anticipate how Newman's JSON reporter behaves when a teardown script (`pm.sendRequest`) executes unconditionally; it logged the teardown's 200 OK status instead of the primary request's 500 Internal Server Error, masking a critical bug until human debugging intervened.

**Why it failed to catch the issues:** These failures stem from the inherent nature of LLMs: they operate on probabilistic text generation rather than actual deterministic execution. The AI lacked the localized, runtime context of the specific Newman reporter implementation and the Express.js framework defaults. It "assumed" standard HTTP behaviors rather than verifying the exact stack's quirks.

**Principles learned about collaborating with AI:** The most critical principle learned is that **AI is a high-speed drafting engine, not an autonomous authority**. The high percentage of `REVISED` statuses in the audit logs highlights that human-in-the-loop verification is mandatory. The human's role shifts from writing manual test cases to orchestrating, reviewing, and steering the AI. Effective collaboration requires establishing strict guardrails—such as the mandatory Human Gates defined in the project's workflow—ensuring the AI pauses for human confirmation on business logic, bug severity, and script execution accuracy before proceeding to the next step.
