# Postman Collection Structure Reference

This document defines the canonical JSON structure for a Postman collection generated by the `api-collection` skill.

> **Source:** [Postman Collection Format v2.1 specification](https://schema.postman.com/collection/json/v2.1.0/draft-07/collection.json)

## Top-Level Collection Structure

```json
{
  "info": {
    "_postman_id": "{{uuid}}",
    "name": "{feature_id} — {METHOD} {PATH}",
    "description": "Generated test collection for {METHOD} {PATH}. Feature: {feature_id}.",
    "schema": "https://schema.getpostman.com/json/collection/v2.1.0/collection.json"
  },
  "variable": [
    {
      "key": "baseUrl",
      "value": "{{baseUrl}}",
      "type": "string"
    }
  ],
  "event": [
    {
      "listen": "prerequest",
      "script": {
        "type": "text/javascript",
        "exec": [
          "// Collection-level Pre-request Script",
          "// 1. Custom header injection",
          "// 2. Auth token management"
        ]
      }
    }
  ],
  "item": []
}
```

## Folder Structure (item Array)

The collection utilizes the **Iteration Router Architecture** to segregate static execution from data-driven looping:

```json
"item": [
  {
    "name": "[Control] Iteration Router",
    "request": {
      "method": "GET",
      "header": [],
      "url": {
        "raw": "https://postman-echo.com/get",
        "protocol": "https",
        "host": ["postman-echo", "com"],
        "path": ["get"]
      }
    },
    "event": [
      {
        "listen": "test",
        "script": {
          "type": "text/javascript",
          "exec": [
            "if (pm.info.iteration > 0) {",
            "    postman.setNextRequest('Data-Driven Template');",
            "}"
          ]
        }
      }
    ]
  },
  {
    "name": "Static TCs",
    "item": [
      { "name": "TC-FR", "item": [], "event": [...] },
      { "name": "TC-ST", "item": [], "event": [...] },
      { "name": "TC-SEC", "item": [], "event": [...] },
      { "name": "TC-SCH", "item": [], "event": [...] },
      { "name": "TC-ERR", "item": [], "event": [...] },
      { "name": "TC-IDP", "item": [], "event": [...] },
      { "name": "TC-RL", "item": [], "event": [...] }
    ]
  },
  {
    "name": "Data-Driven TCs",
    "item": [
      { "name": "Data-Driven Template", "request": {...}, "event": [...] }
    ]
  }
]
```

## Request Item Structure

Each TC maps to one request item inside its category folder:

```json
{
  "name": "TC-{feature_id}-FR-001 — {TC Title}",
  "event": [
    {
      "listen": "prerequest",
      "script": {
        "type": "text/javascript",
        "exec": ["// Request-level pre-request (only if needed)"]
      }
    },
    {
      "listen": "test",
      "script": {
        "type": "text/javascript",
        "exec": [
          "pm.test('Status is 200', function() {",
          "  pm.response.to.have.status(200);",
          "});",
          "",
          "pm.test('Response has id field', function() {",
          "  const body = pm.response.json();",
          "  pm.expect(body).to.have.property('id');",
          "  pm.expect(body.id).to.be.a('number');",
          "});"
        ]
      }
    }
  ],
  "request": {
    "method": "POST",
    "header": [
      {
        "key": "Content-Type",
        "value": "application/json"
      }
    ],
    "body": {
      "mode": "raw",
      "raw": "{\n  \"name\": \"{{name}}\",\n  \"email\": \"{{email}}\",\n  \"password\": \"{{password}}\"\n}",
      "options": {
        "raw": { "language": "json" }
      }
    },
    "url": "{{baseUrl}}/api/register"
  }
}
```

## Environment File Structure (`local.json`)

```json
{
  "id": "{uuid}",
  "name": "Local",
  "values": [
    {
      "key": "baseUrl",
      "value": "http://localhost:3000",
      "type": "default",
      "enabled": true
    },
    {
      "key": "userToken",
      "value": "",
      "type": "default",
      "enabled": true
    },
    {
      "key": "adminToken",
      "value": "",
      "type": "default",
      "enabled": true
    }
  ],
  "_postman_variable_scope": "environment",
  "_postman_exported_at": "{ISO datetime}",
  "_postman_exported_using": "api-collection skill"
}
```

**Merge rule:** When updating `local.json`, compare `key` fields. Add only entries whose `key` does not already exist. Never modify existing `value` fields.

## Data File Formats

### CSV (`data-domain.csv`)

One column per variable placeholder used in data-driven requests. One row per TC partition.

```csv
name,email,password,expected_status,expected_message
"Valid User","valid@example.com","Password123!",200,"User registered successfully"
"","valid@example.com","Password123!",400,""
"Valid User","not-an-email","Password123!",400,""
"Valid User","valid@example.com","short",400,""
"Valid User","valid@example.com","",400,""
```

Column naming rules:

- Use snake_case
- Include `expected_status` and `expected_message` columns to allow assertions to vary per row
- Do not include columns for values that never change across rows

### JSON (`data-security.json`)

Use when payloads contain special characters, nested structure, or require array values that CSV cannot represent cleanly.

```json
[
  {
    "tc_id": "TC-FR01-SEC-001",
    "field": "email",
    "payload": "' OR '1'='1",
    "expected_status": 400,
    "attack_type": "SQL Injection"
  },
  {
    "tc_id": "TC-FR01-SEC-002",
    "field": "name",
    "payload": "<script>alert(1)</script>",
    "expected_status": 400,
    "attack_type": "XSS"
  }
]
```
