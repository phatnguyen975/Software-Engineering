# Coding Rules — wat-build

Mandatory rules for all Playwright TypeScript files generated by this skill. These rules apply to spec files, POM files, and fixture files alike unless a rule explicitly states otherwise.

## 1. Imports

```typescript
// CORRECT — always import test and expect from the project fixture entry point
import { test, expect } from "@fixtures/base.fixture";
import { loadTestData } from "@helpers/data-loader";

// WRONG — never import directly from @playwright/test in spec files
import { test, expect } from "@playwright/test";
```

## 2. Selector Hierarchy

Apply selectors in this priority order. Move to the next level only when the higher-priority option is not available in the DOM.

| Priority        | Selector type | Example                                         |
| --------------- | ------------- | ----------------------------------------------- |
| 1 (highest)     | `getByRole`   | `page.getByRole('button', { name: /submit/i })` |
| 2               | `getByLabel`  | `page.getByLabel('Email')`                      |
| 3               | `getByTestId` | `page.getByTestId('email-input')`               |
| 4               | `getByText`   | `page.getByText('Registration successful')`     |
| 5 (last resort) | CSS selector  | `page.locator('[data-id="submit"]')`            |

**Never use:**

- CSS class selectors (`.btn-primary`, `.form-error`)
- XPath
- Position-based selectors (`:nth-child`, `:nth-of-type`)

## 3. Waiting and Assertions

```typescript
// CORRECT — web-first assertions auto-retry until the condition is met
await expect(page.getByRole("alert")).toBeVisible();
await expect(page).toHaveURL("/login");
await expect(page.getByLabel("Email")).toHaveValue("");

// WRONG — arbitrary delays mask the real problem
await page.waitForTimeout(2000);

// ACCEPTABLE — use waitFor only when no assertion-based alternative exists
await page.getByRole("button").waitFor({ state: "visible" });
```

**Required: at least 3 distinct assertion pattern types per spec file.**

Assertion patterns (choose at least 3 different ones):

| Pattern       | Example                                                              |
| ------------- | -------------------------------------------------------------------- |
| Visibility    | `expect(locator).toBeVisible()` / `toBeHidden()`                     |
| URL           | `expect(page).toHaveURL('/path')` or regex                           |
| Text content  | `expect(locator).toHaveText('...')` / `toContainText('...')`         |
| Input value   | `expect(locator).toHaveValue('...')`                                 |
| Element count | `expect(locator).toHaveCount(n)`                                     |
| Element state | `expect(locator).toBeEnabled()` / `toBeDisabled()` / `toBeChecked()` |
| Attribute     | `expect(locator).toHaveAttribute('attr', 'value')`                   |

## 4. Data Loading

```typescript
// CORRECT — load from JSON file; type the record shape
import { loadTestData } from "@helpers/data-loader";

interface RegistrationCase {
  tc_id: string;
  description: string;
  inputs: {
    fullName: string;
    email: string;
    password: string;
    confirmPassword: string;
  };
  expected: {
    outcome: "success" | "error";
    message: string;
    redirect?: string;
  };
}

const cases = loadTestData<RegistrationCase>("fr-01-registration.json");
```

**Rules:**

- All input values must come from the JSON data file — no hardcoded strings in spec.
- Define a TypeScript interface for each data record shape.
- The `tc_id` field in each JSON record must match the test name prefix.

## 5. Test Iteration

```typescript
// CORRECT — for...of loop
for (const tc of cases) {
  test(`${tc.tc_id}: ${tc.description}`, async ({ page }) => {
    // test body
  });
}

// WRONG — test.each() is not supported in this project
test.each(cases)("...", async (tc, { page }) => {});
```

## 6. Test Isolation

```typescript
// CORRECT — each test is self-contained; beforeEach resets state
test.describe("FR-01: Account Registration", () => {
  test.use({ storageState: { cookies: [], origins: [] } }); // unauthenticated

  let registerPage: RegisterPage;

  test.beforeEach(async ({ page }) => {
    registerPage = new RegisterPage(page);
    await registerPage.navigate("/register");
  });

  // each test() block only uses registerPage and data from its own TC record
});
```

**Rules:**

- No shared mutable state between `test()` blocks.
- `beforeEach` sets up state; `afterEach` or fixture teardown cleans it up.
- Never rely on a previous test having run.
- No `test.only()` in committed code.

## 7. Authentication

```typescript
// Features that DO require auth — storageState injected via playwright.config.ts project settings.
// No action needed in the spec file.

// Features that DO NOT require auth — override at file level:
test.use({ storageState: { cookies: [], origins: [] } });

// WRONG — never log in manually inside a test block
test("...", async ({ page }) => {
  await page.goto("/login");
  await page.fill("[name=email]", "..."); // ← never do this
});
```

## 8. Page Object Model Rules

```typescript
// CORRECT POM structure
import { type Page, type Locator } from '@playwright/test';
import { BasePage } from '../base.page';

export class RegisterPage extends BasePage {
  readonly url = '/register';

  // Locator getters — noun names, no assertions
  get emailInput(): Locator { return this.page.getByLabel('Email'); }
  get submitButton(): Locator { return this.page.getByRole('button', { name: /register/i }); }
  get emailError(): Locator { return this.page.getByRole('alert').filter({ hasText: 'email' }); }

  // Action methods — verb names, no assertions
  async fillForm(data: { fullName: string; email: string; password: string; confirmPassword: string }): Promise<void> {
    await this.page.getByLabel('Full Name').fill(data.fullName);
    await this.emailInput.fill(data.email);
    await this.page.getByLabel('Password').fill(data.password);
    await this.page.getByLabel('Confirm Password').fill(data.confirmPassword);
  }

  async submit(): Promise<void> {
    await this.submitButton.click();
  }
}

// WRONG — assertions inside POM
async fillAndAssert(email: string): Promise<void> {
  await this.emailInput.fill(email);
  await expect(this.emailInput).toHaveValue(email); // ← never assert in POM
}
```

## 9. Fixture Rules

Create a `*.fixture.ts` file when the feature requires:

- API calls to seed or clean up data before/after each test.
- Navigation to a specific pre-condition state that is more than `goto()`.
- Shared page objects that need lifecycle management across tests.

Do **not** create a fixture file for features where `beforeEach` with `goto()` suffices.

```typescript
// CORRECT fixture structure
import { test as base } from "@playwright/test";
import { RegisterPage } from "../pages/web/register.page";

type RegisterFixtures = { registerPage: RegisterPage };

export const registerFixtures = {
  registerPage: async (
    { page }: { page: Page },
    use: (r: RegisterPage) => Promise<void>,
  ) => {
    const registerPage = new RegisterPage(page);
    await registerPage.navigate(registerPage.url);
    await use(registerPage);
    // teardown if needed
  },
};
```

Register in `fixtures/base.fixture.ts`:

```typescript
import { registerFixtures, type RegisterFixtures } from "./register.fixture";
export const test = base.extend<RegisterFixtures>({ ...registerFixtures });
```

## 10. Test Naming

```typescript
// CORRECT — TC-ID prefix ensures traceability
test("TC-FR01-001: Register account with valid data", async ({ page }) => {});

// When using for...of loop — TC-ID comes from data record
test(`${tc.tc_id}: ${tc.description}`, async ({ page }) => {});

// WRONG — no TC-ID, not traceable
test("valid registration", async ({ page }) => {});
```
